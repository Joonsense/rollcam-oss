# 실기기 테스트 (스펙 §8 4주차)

대상 3종: 삼성 갤럭시(One UI), 구글 픽셀, 중저가(램 4GB 이하). 에뮬레이터에서 못 보는 것만 적었다.

## 설치

```
npm run android-release            # release/rollcam-<ver>-vc<n>.aab
bundletool build-apks --bundle=release/rollcam-0.1.0-vc1.aab --output=/tmp/rollcam.apks --connected-device --ks=... (업로드 키)
bundletool install-apks --apks=/tmp/rollcam.apks
```
또는 Play 내부 테스트 트랙.

## 알려진 에뮬레이터 한계 (실기기에서 확인할 것)
- 에뮬레이터 정지 사진은 검은 프레임이라 실제 사진 현상은 실기기에서만 확인된다 (개발 빌드는 files/debug.jpg 로 대체).
- `adb emu geo fix` 가 앱 위치에 반영되지 않았다. 위치별 필름 결정은 실기기로 확인.
- 31장 합성 메모리: 에뮬레이터 19장은 문제없었음.

## 에뮬레이터에서 미리 확인한 것 (2026-10-22, rollcam_p7, 개발 빌드)
- 사진 방향(#3): EXIF Orientation 1·3·6·8 JPEG 를 files/debug.jpg 로 현상 → 네 경우 모두 세로로 바르게 섬 (Skia 디코딩이 EXIF 를 반영). 실기기에서는 폰을 가로로 들고 찍었을 때 카메라가 방향 정보를 붙이는지만 보면 된다.
- 메모리(#12): 9월 30장 롤에서 롤 화면 PSS 약 312MB, 롤 공유 합성 중 최고 약 372MB (합성이 약 60MB 더함). Skia 는 사진을 그릴 때 디코딩하므로 한 달 치를 미리 읽어도 메모리는 압축 JPEG 크기뿐이었다. 램 4GB 이하 기기에서 이 값으로 꺼지는지가 실기기 확인 포인트.
- 셔터→현상(#2): 개발 빌드 Hermes 에서 촬영 약 0.5초 + 현상 약 0.2~0.6초, 필름 LUT 는 미리 굽거나 디스크 캐시(1~63ms).

## release 빌드 에뮬레이터 확인 방법 (2026-10-25)
- 출시 전에는 개발 빌드가 아니라 release APK 로 꼭 띄운다. 0.3.8 에서 R8 이 WorkManager(위젯)의 Room `WorkDatabase_Impl` 생성자를 지워 release 에서만 실행 즉시 종료됐다(app.json `expo-build-properties` keep 규칙으로 수정). release-check 는 매니페스트만 보므로 이런 건 못 잡는다.
  - `npm run android-release` 뒤 `cd android && ./gradlew assembleRelease -Pandroid.injected.signing.*=...`(값은 `scripts/android-release.mjs` 가 읽는 서명 env 파일) → `adb install -r android/app/build/outputs/apk/release/app-release.apk`. android-release 가 prebuild 하면서 이전 APK 를 지우니 순서는 AAB 먼저.
- 툴체인: `brew install openjdk@21` + `brew install --cask android-commandlinetools`, `sdkmanager "platform-tools" "emulator" "platforms;android-36" "build-tools;36.0.0" "system-images;android-36;google_apis;arm64-v8a"`. NDK 는 첫 빌드가 받아 오고 Skia 네이티브 컴파일로 첫 빌드만 30분 남짓.
- AVD `rollcam_p6`(포트 5580): 창 모드는 호스트 GPU 오류(bad color buffer handle)로 죽은 적이 있어 `emulator -avd rollcam_p6 -port 5580 -no-window -no-snapshot -no-audio -no-boot-anim -gpu swiftshader_indirect` 로 띄운다.
- 조작: `adb exec-out screencap -p` + `adb shell input tap x y`. 카메라 화면은 카운트다운이 계속 돌아 `uiautomator dump` 가 멈추니 좌표로 누른다. 시스템 프로세스를 `pkill -f` 로 건드리지 말 것(시스템 UI 가 죽음).
- 데모 롤: `python3 scripts/demo-roll.py <dir> --zip en|ko` 로 만든 zip 을 `adb push ... /sdcard/Download/` 후 설정 > 롤 가져오기. release 빌드에서도 롤이 채워져 스토어 스크린샷·기능 확인에 쓴다. 오늘·1년 전 오늘 칸도 들어 있다.
- 깨끗한 상태 막대: `settings put global sysui_demo_allowed 1` 뒤 `am broadcast -a com.android.systemui.demo -e command enter|clock|battery|network|notifications ...`.
- 시간대 바꾸기: `adb shell service call alarm 3 s16 Asia/Tokyo` (끝나면 Asia/Seoul 로 되돌림).
- 영어 스토어 스크린샷: 위 데모 롤을 영어 폰에서 찍어 `store/out/en/raw-*` → `python3 scripts/store-frame.py --lang en`(Pillow 필요) → `npm run play-publish -- --no-bundle --images` 가 en-US 에는 store/out/en 을 올린다.
